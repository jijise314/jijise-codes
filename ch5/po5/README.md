# 순차 탐색 vs 이진 탐색 트리(BST) 탐색 비교

0~1,000 사이의 서로 다른 정수 100개를 배열(발생 순서, 정렬 안 함)과 BST에 저장하고, 탐색 키 50개에 대해 두 방법의 **숫자 비교 횟수**를 비교했습니다.

- **비교 횟수 기준:** 순차 탐색은 배열 원소 1개와 비교할 때마다 1회, BST는 노드 1개와 비교할 때마다 1회

## 실행 결과

| 항목 | 값 |
|---|---|
| BST 생성 총 비교 횟수 | 640 |
| 트리 높이 | 16 |
| 탐색 결과 | 성공 4회, 실패 46회 |

| 구분 | 총 비교 횟수 | 평균 비교 횟수 |
|---|---|---|
| 순차 탐색 | 4,767 | 95.34 |
| BST 탐색 | 454 | 9.08 |
| BST 생성 + 탐색 | 1,094 | – |

## 분석

### 1. 두 탐색 방법의 성능 차이

BST 탐색이 순차 탐색보다 약 **10.5배** 적게 비교했습니다.

순차 탐색은 정렬되지 않은 배열을 처음부터 하나씩 비교하므로, 값이 없으면 100개를 모두 비교해야 실패를 확정할 수 있습니다. 저장된 값이 범위의 약 10%뿐이라 50개 중 46개가 실패했고, 그 46번 모두 100회씩 비교했기 때문에 평균이 95.34로 높게 나왔습니다.

BST는 한 번 비교할 때마다 왼쪽 또는 오른쪽 서브트리 전체를 제외하므로, 비교 횟수가 트리 높이(16)를 넘지 않습니다. 실패 탐색도 경로 하나만 따라가면 되어 평균 9.26회로 끝났습니다. 예를 들어 439는 배열의 96번째 값이라 순차 탐색으로 96회가 걸렸지만, BST에서는 11회 만에 찾았습니다.

### 2. BST 생성 비용을 고려한 성능 차이

배열은 저장할 때 비교가 필요 없지만, BST는 삽입 위치를 찾느라 640회를 비교했습니다. 그래도 생성과 탐색을 합한 비용은 **BST 1,094회 vs 배열 4,767회**로 BST가 약 4.4배 효율적이었습니다. 탐색 1회마다 평균 86회씩 비교가 줄어서, 50회 탐색 동안 생성 비용을 충분히 상쇄했기 때문입니다. 다만 탐색 횟수가 아주 적다면 생성 비용이 더 클 수 있으므로, BST는 **여러 번 반복해서 탐색할 때** 유리합니다.

### 3. BST 구조에 따른 탐색 성능

BST의 비교 횟수는 노드의 깊이에 따라 달라지고, 깊이는 삽입 순서로 결정됩니다. 100개 노드의 최소 높이는 7인데, 이번 트리는 높이가 16이었습니다. 335, 348, 351, 356, 376이 우연히 커지는 순서로 삽입되면서 이 부분이 한 줄로 길어졌기 때문입니다. 그 결과 이 구간을 지나는 키(378, 384, 390, 391, 399)는 15~16회를 비교했지만, 고르게 퍼진 오른쪽 서브트리의 키(988, 1000)는 4회 만에 끝났습니다.

이런 일렬 구조가 트리 전체로 퍼지는 것이 정렬된 데이터를 삽입한 경우입니다. 이때 트리는 높이가 100인 편향 트리가 되어 탐색 비교가 순차 탐색과 비슷한 O(n)으로 늘어나고, 생성 비용도 O(n²)으로 커집니다. 따라서 데이터가 정렬된 순서로 들어올 수 있다면 AVL 트리 같은 균형 이진 탐색 트리를 사용하는 것이 좋습니다.

## 결론

BST는 생성 비용을 포함해도 순차 탐색보다 훨씬 적은 비교로 탐색했습니다. 하지만 그 성능은 트리가 얼마나 균형 잡혀 있는지에 달려 있습니다.
