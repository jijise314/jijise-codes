# 퀵 정렬 피벗 선택 방법에 따른 성능 비교

## 1. 개요

퀵 정렬에서 피벗을 고르는 방법 세 가지를 같은 무작위 정수 데이터에 적용했습니다. 정렬하는 동안 발생한 **데이터 값 사이의 비교 횟수**를 측정해 성능을 비교했습니다.

| 방법 | 피벗 선택 방식 |
|---|---|
| First | 현재 구간의 첫 번째 원소 |
| Random | 현재 구간에서 무작위 위치의 원소. 분할할 때마다 새로 선택 |
| Median-3 | 첫 번째·가운데·마지막 원소 중 크기상 가운데 값 |

- 세 방법은 피벗을 골라 구간의 첫 번째 위치로 옮기는 부분만 다릅니다. 분할 알고리즘(`partition`)은 모두 같은 함수를 사용합니다.
- 비교 횟수는 데이터 값끼리 비교하는 `LESS()` 함수가 호출된 횟수입니다. 분할에서 피벗과 비교한 횟수와 Median-3에서 중앙값을 정하는 비교가 포함됩니다. 인덱스 검사, 무작위 위치 생성, 데이터 이동은 포함하지 않았습니다.
- 데이터 크기마다 원본을 한 번 생성하고, 세 방법에는 같은 원본의 복사본을 사용했습니다. 값 범위는 0 ~ 99,999이고 중복을 허용합니다.
- 모든 실험에서 정렬 결과가 오름차순인지 확인했으며, 모두 정상이었습니다.

### 파일 구성

| 파일 | 내용 |
|---|---|
| `quicksort.h` | 피벗 종류, 비교 횟수 변수, 함수 선언 |
| `quicksort.c` | 피벗 선택, 분할, 재귀·반복 퀵 정렬, 데이터 생성, 정렬 확인, 타이머 |
| `main.c` | 비교 횟수 실험과 실행시간 실험, 결과 출력 |

## 3. 분석

### 데이터 크기에 따른 변화
n이 2배가 될 때 비교 횟수는 세 방법 모두 약 **2.1 ~ 2.3배**로 늘었습니다. O(n)이면 2배, O(n²)이면 4배가 되어야 하므로, 이 증가율은 **O(n log n)** 에 해당합니다. 비교 횟수 ÷ n log₂ n이 n과 상관없이 거의 일정한 것도 같은 결론을 뒷받침합니다.

### 방법별 성능 차이
- **Median-3**는 모든 크기에서 비교 횟수가 가장 적었습니다. 비율 범위도 1.15 ~ 1.17로 가장 좁아 결과가 안정적이었습니다.
- **First와 Random**은 비슷했습니다. 대부분 Random이 조금 적었지만, n = 2,000에서는 오히려 더 많아 일관된 차이는 없었습니다.

### 피벗이 비교 횟수에 영향을 주는 이유
분할 한 번의 비교 횟수는 피벗과 상관없이 구간 길이 m 정도로 같습니다. 차이를 만드는 것은 **분할이 얼마나 고르게 되느냐**입니다.
- 피벗이 중앙값에 가까우면 구간이 1 : 1로 나뉘어 재귀 깊이가 log₂ n이 되고, 비교 횟수가 가장 적습니다.
- 피벗이 최솟값이나 최댓값이면 구간이 원소 1개만 줄어서 깊이가 n이 되고, 비교 횟수는 O(n²)이 됩니다.

방법별로 보면 다음과 같습니다.
- **First:** 무작위 데이터에서는 Random과 같은 효과를 내서 결과도 비슷했습니다. 하지만 정렬된 데이터에서는 매번 최솟값이 피벗이 되어 O(n²)으로 느려집니다.
- **Random:** 입력 순서와 상관없이 평균 성능이 보장됩니다. 다만 한 번 한 번의 선택은 운에 달려 있어 분할이 치우칠 수 있습니다.
- **Median-3:** 세 값의 중앙값은 최솟값이나 최댓값이 될 수 없고, 실제 중앙값에 가까울 확률이 높습니다. 중앙값을 고르느라 분할마다 2 ~ 3번 더 비교하지만, 분할이 고르게 되어 전체 비교 횟수가 줄어듭니다. 이론값으로도 Random은 약 1.39 n log₂ n, Median-3는 약 1.19 n log₂ n번 비교합니다.

## 4. [보너스] 재귀적 vs 반복적 퀵 정렬

조건: n = 10,000, Median-3 피벗, 정렬 구간만 1,000번 측정한 평균입니다. 데이터 생성과 배열 복사 시간은 제외했습니다.

| 방법 | 평균 실행시간 |
|---|---:|
| 재귀적 | 0.6316 ms |
| 반복적 | 0.6220 ms |

차이는 약 1.5 %로, 측정 오차 수준입니다. **두 방법의 실행시간은 사실상 같습니다.** 이유는 다음과 같습니다.
- **수행하는 분할이 같습니다.** 두 방법은 같은 피벗과 같은 분할 함수를 쓰므로 비교 횟수와 데이터 이동 횟수가 같습니다. 다른 점은 다음에 처리할 구간을 기억하는 방식(콜 스택 또는 배열 스택)뿐입니다.
- **함수 호출 비용이 작습니다.** 함수를 한 번 호출하거나 스택에 push·pop하는 비용은 수 ns 수준입니다. 분할하면서 비교하고 교환하는 시간이 전체의 대부분을 차지합니다.
- **재귀 깊이가 얕습니다.** Median-3로 분할이 고르게 되어 재귀 깊이가 약 log₂ n에 그쳤습니다. 그래서 콜 스택 부담이 거의 없었습니다.

## 5. 결론

1. 세 방법 모두 무작위 데이터에서 비교 횟수가 **n log n에 비례해** 늘었습니다.
2. 피벗 선택은 분할 한 번의 비용이 아니라 **분할이 얼마나 고르게 되는지**를 바꿉니다. 그 결과 재귀 깊이와 전체 비교 횟수가 달라집니다.
3. **Median-of-Three**가 비교 횟수, 결과의 안정성, 정렬된 입력에 대한 강함 모두에서 가장 효과적이었습니다.
4. 재귀적 방법과 반복적 방법은 같은 분할을 수행하므로 실행시간이 사실상 같습니다. 반복적 방법의 장점은 콜 스택 오버플로를 피할 수 있다는 안정성에 있습니다.
