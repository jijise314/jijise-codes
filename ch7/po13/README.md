# 병합 정렬 vs 퀵 정렬 성능 비교

병합 정렬과 피벗 선택 방법이 다른 퀵 정렬 3종을 같은 무작위 데이터로 실행하여 **비교 횟수, 실행 시간, 추가 메모리**를 비교합니다.

| 알고리즘 | 설명 |
|---|---|
| Merge Sort | 재귀 병합 정렬 (크기 n 임시 배열 사용) |
| Quick (First) | 첫 번째 원소를 피벗으로 사용 |
| Quick (Random) | 무작위 원소를 피벗으로 사용 |
| Quick (Median3) | 첫·가운데·마지막 원소의 중앙값을 피벗으로 사용 |

## 파일 구성

```
main.c                    실험 진행 및 결과 출력
common.h / common.c       비교 카운터, 메모리 측정, 데이터 생성 등 공용 기능
quicksort.h / quicksort.c 퀵 정렬
mergesort.h / mergesort.c 병합 정렬
```

## 측정 방법

### 실험 조건
- 데이터 크기: **1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000**
- 데이터: 0 ~ 99,999 범위의 무작위 정수 (`srand(time(NULL))`로 실행마다 다른 데이터)
- 공정성: 크기마다 원본 배열을 한 번 만들고, 모든 알고리즘이 **같은 원본의 복사본**을 정렬

### 비교 횟수
전역 카운터 `g_compare`를 사용합니다. 데이터 값끼리의 비교는 모두 `common.h`의 `LESS(x, y)` 함수를 거치며, 호출될 때마다 카운터가 1 증가합니다. 퀵 정렬의 중앙값 선택(`median_of_three`)에서 하는 비교도 포함됩니다. 인덱스 비교(`i <= high` 등)는 세지 않습니다.

### 실행 시간
- 같은 정렬을 **50회(`REPEAT`) 반복**한 평균값입니다.
- 매 반복 전 원본을 `work` 배열로 복사하며, **복사는 측정 구간 밖**에서 합니다.
- 반복할 때마다 정렬 결과도 검사합니다.

### 메모리 사용량 (최대 추가 메모리)

```
Memory = 재귀 스택 최대 깊이(바이트) + 힙 임시 배열 최대 크기(바이트)
```

- **스택**: `mem_reset()`이 정렬 호출 직전의 스택 주소를 기준점으로 저장합니다. 재귀 함수와 `partition`/`merge`에 넣은 `STACK_PROBE()` 매크로가 현재 지역 변수 주소를 기록하고, 가장 낮은 주소와 기준점의 차이를 최대 스택 사용량으로 봅니다. (스택이 낮은 주소 방향으로 자란다고 가정합니다.)
- **힙**: `tracked_malloc` / `tracked_free`로 할당량을 추적하여 최댓값(`g_heap_peak`)을 기록합니다. 병합 정렬의 임시 배열(`sizeof(int) × n`)이 여기에 해당하며, 퀵 정렬은 힙을 사용하지 않습니다.
- 스택 측정값은 컴파일러, 최적화 옵션, 운영체제에 따라 달라질 수 있습니다.

## 출력 형식

```

(실행시간: 50회 측정 평균, 메모리: 최대 추가 메모리 = 재귀 스택 + 임시 배열)

Data Size : 1000

Algorithm       Comparisons    Time(ms)    Memory(Bytes)
--------------------------------------------------------
Merge Sort      8708           0.0451      5073
Quick (First)   12190          0.0196      1440
Quick (Random)  11621          0.0698      1248
Quick (Median3) 11459          0.0193      1056

정렬 결과 확인 : 정상 (오름차순)
```

정렬이 잘못된 알고리즘이 있으면 해당 행 끝에 `[오류: 정렬되지 않음]`이 표시되고, 마지막 줄이 `오류 발생`으로 바뀝니다.

## 결과 분석

- **비교 횟수**: 병합 정렬이 가장 적습니다. 병합 정렬은 최악의 경우에도 약 n log₂ n번 비교하지만, 퀵 정렬은 평균적으로 약 1.39 n log₂ n번 비교합니다. 퀵 정렬 중에서는 Median3이 가장 적은데, 피벗이 중앙값에 가까워 분할이 더 균등해지기 때문입니다.
- **실행 시간**: 비교 횟수는 더 많지만 Quick (First)과 Quick (Median3)이 병합 정렬보다 대체로 빠릅니다. 퀵 정렬은 제자리에서 정렬하고, 병합 정렬은 매 병합마다 임시 배열로 복사했다가 다시 되돌리는 데이터 이동 비용이 있기 때문입니다. Quick (Random)이 느린 것은 분할마다 `rand()`를 두 번 호출하는 비용 때문입니다.
- **메모리**: 병합 정렬은 임시 배열 때문에 O(n)으로 n에 비례해 늘어납니다 (n = 16,000에서 약 64KB). 퀵 정렬은 재귀 스택만 쓰므로 평균 O(log n)이며, n이 16배 늘어도 1~2KB 수준을 유지합니다.
- **데이터가 무작위이므로** Quick (First)도 최악의 경우(O(n²))가 나오지 않습니다. 이미 정렬된 데이터나 역순 데이터를 넣으면 Quick (First)은 비교 횟수가 약 n²/2로 늘고 재귀 깊이도 n에 가까워집니다. Random과 Median3은 이런 경우를 피하기 위한 방법입니다.
