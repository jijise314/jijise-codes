# 퀵 정렬 vs AVL 트리 정렬 성능 비교

## 1. 구현 개요

| 파일 | 내용 |
|---|---|
| `main.c` | 데이터·연산 생성, 측정, 검증, 출력 |
| `common.c/h` | 비교·이동 횟수 카운터, 메모리 측정, 난수·시간 함수 |
| `quicksort.c/h` | 퀵 정렬 (이전 과제 코드) |
| `sorted_array.c/h` | 정렬된 배열의 선형 탐색 삽입·삭제 |
| `avl.c/h` | AVL 트리 (삽입·삭제·회전·중위 순회) |

- **퀵 정렬**: 피벗 선택은 **Median-of-3** 방식입니다. 정렬 후 배열에서 선형 탐색으로 위치를 찾고, 원소를 한 칸씩 밀거나 당겨 삽입·삭제합니다.
- **AVL 트리**: 중복 값은 노드의 `count`로 저장합니다. 삭제할 때 `count > 1`이면 개수만 줄입니다. 균형은 LL·LR·RR·RL 회전으로 복구합니다.
- **연산 생성**: n의 20%만큼 연산을 미리 생성해 두 자료구조에 같은 순서로 적용합니다. 난수 생성 시간은 측정에서 제외됩니다.

## 2. 측정 기준

- **수행시간**: 정렬 시작부터 모든 삽입·삭제가 끝날 때까지 걸린 시간의 10회 평균입니다.
- **비교 횟수**: 데이터 값끼리 비교한 횟수(`LESS()` 호출 수)입니다. AVL의 높이·균형 인수 비교는 제외합니다.
- **이동 횟수**: 데이터 값을 복사·대입한 횟수입니다.
  - 배열: `swap` 1회 = 3회, 원소 한 칸 이동 = 1회
  - AVL: 노드에 값 대입 = 1회. 회전 등 포인터 변경은 제외합니다.
- **메모리**: 최대 힙 사용량(배열 용량 또는 노드 수 × 32바이트)에 최대 호출 스택을 더한 값입니다.

## 4. 비교·분석

### 4.1 수행시간 및 비교 횟수

정렬 단계만 보면 두 방법 모두 O(n log n)이라 비교 횟수가 비슷합니다(n = 20,000에서 약 33만 회 대 39만 회). 시간은 오히려 퀵 정렬이 2배 이상 빠릅니다. 배열은 연속된 메모리라 캐시를 잘 활용하지만, AVL은 노드마다 `malloc`을 호출하고 흩어진 노드를 포인터로 따라가야 하기 때문입니다.

차이는 삽입·삭제 단계에서 생깁니다.
- 배열은 연산마다 선형 탐색으로 평균 n/2번 비교합니다.
- AVL은 트리 높이(약 17)만큼만 내려가면 되므로 약 20번 비교합니다.

그 결과 n = 20,000에서 퀵 정렬 쪽 전체 비교 횟수의 99% 이상이 삽입·삭제에서 나왔습니다. 전체적으로 비교 횟수는 87배, 시간은 5.5배 차이가 났습니다.

### 4.2 데이터 이동 횟수

이동 횟수는 n = 20,000에서 약 1,260배로 차이가 가장 큽니다.
- **배열**은 순서가 곧 메모리상의 위치입니다. 그래서 값을 하나 넣거나 뺄 때마다 그 뒤의 원소를 모두 밀거나 당겨야 합니다(1회 평균 수천 번).
- **AVL**은 순서를 포인터 연결로 표현합니다. 새 노드에 값을 한 번 대입하고 포인터만 연결하면 되며, 회전도 포인터만 바꿉니다.

### 4.3 메모리 사용량

배열은 원소당 4바이트만 쓰지만, AVL 노드는 값·개수·높이와 포인터 2개로 32바이트입니다. 중복 값을 `count`로 묶어 노드 수가 줄었지만, AVL은 여전히 약 6.5배의 메모리를 사용했습니다. 두 구조 모두 공간 복잡도가 O(n)이라, 이 비율은 데이터 크기와 관계없이 거의 일정합니다.

### 4.4 데이터 크기 증가에 따른 변화

n이 20배(1,000 → 20,000) 커졌을 때 비교 횟수의 증가는 다음과 같습니다.
- **퀵 정렬 + 배열**: 348배 늘었습니다. 연산 수(0.2n)와 연산 1회의 비용(O(n))이 함께 커져 전체가 **O(n²)**(이론상 400배)에 가깝습니다.
- **AVL**: 29.7배 늘었습니다. **O(n log n)**(이론상 28.7배)과 거의 일치합니다.

그래서 n = 1,000에서는 배열이 빠르지만, n = 2,000 부근에서 시간이 비슷해지고, 그 뒤로는 AVL이 앞서며 차이가 계속 벌어집니다.

### 4.5 삽입·삭제가 반복되는 환경에 유리한 자료구조

**AVL 트리가 유리합니다.** 회전으로 높이를 log n 수준으로 유지하므로 탐색·삽입·삭제가 항상 O(log n)입니다. 또 값을 옮기지 않고 포인터 연결만 바꿔 정렬 상태를 유지합니다. 정렬된 배열은 이진 탐색으로 비교 횟수를 줄여도 원소 이동이 O(n)이라 한계가 남습니다.

반대로 다음과 같은 경우에는 배열이 더 적합합니다.
- 데이터가 작을 때
- 삽입·삭제가 드물고 정렬·조회 위주일 때
- 메모리가 부족할 때
