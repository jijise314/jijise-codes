# 힙 정렬, 퀵 정렬 및 병합 정렬의 성능 비교

무작위 정수 데이터(0~99,999, 중복 허용)에 대해 힙 정렬, 병합 정렬, 퀵 정렬(First / Random / Median3)의 비교 횟수, 실행시간, 최대 추가 메모리를 측정하고 비교한다.

- n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000, 모든 알고리즘은 같은 원본의 복사본을 정렬
- 모든 정렬 결과가 오름차순인지 `is_sorted()`로 확인함 → **모두 정상**

## 1. 측정 방법

- **비교 횟수**: 모든 값 비교를 `LESS()`로만 수행하고, 호출마다 `g_compare`를 1 증가시킨다. 힙 구성 및 복구 과정의 비교와 Median3의 피벗 선택 비교도 포함하며, 인덱스·종료 조건 검사는 제외한다.
- **실행시간**: 정렬 함수 호출 직전부터 반환 직후까지만 `now_ms()`로 측정한다. 데이터 생성, 배열 복사, 출력은 제외한다. 같은 데이터로 50회 반복한 평균을 사용한다.
- **메모리 사용량**: 호출 스택 최대 사용량과 동적 할당 최대 사용량을 더한 값이다. 원본 배열은 공통 비용이므로 제외한다.
  - 스택: 정렬 직전 지역 변수 주소를 기준점으로 잡는다. 각 정렬 함수의 `STACK_PROBE()`가 최저 주소를 기록하고, 사용량은 `기준점 − 최저 주소`로 계산한다. 복귀 주소, 저장 레지스터, 지역 변수가 모두 포함된 실제 프레임 크기가 반영된다.
  - 동적 할당: `tracked_malloc()`이 최대 할당량을 기록한다. 병합 정렬의 임시 배열(4n B)만 해당한다.
  - 참고로 GCC `-O2`에서 프레임 크기는 `quick_sort_recursive`가 64 B, `merge_sort_rec`가 96 B다. 절대값은 컴파일러와 빌드 옵션에 따라 달라진다.

## 3. 분석

### 3.1 비교 횟수

n이 2배가 되면 비교 횟수는 약 2.1~2.3배가 되어, n log n에 비례해 증가한다. 비교 횟수를 n·log₂n으로 나눈 상수는 병합 약 0.9, 퀵 약 1.2, 힙 약 1.8이다.

- **병합**: 병합할 때만 비교하며, 한쪽 구간이 먼저 끝나면 나머지는 비교 없이 복사한다. 그래서 비교가 가장 적다 (≈ n log₂n − 1.25n).
- **힙**: `sift_down`에서 한 레벨마다 2회 비교한다(두 자식 중 큰 쪽 선택, 부모와 비교). 루트로 올린 작은 값이 거의 바닥까지 내려가므로 약 2n log₂n에 가까워 가장 많다.
- **퀵**: 분할할 때 원소마다 피벗과 약 1회 비교한다. 분할이 반반으로 나뉘지 않아 병합보다 25~35% 많다.

### 3.2 실행시간

n = 20,000 기준으로 Quick(First) 1.50 ms, Quick(Median3) 1.62 ms, Merge 1.98 ms, Quick(Random) 1.99 ms, Heap 2.07 ms 순이다. 비교 횟수와 순서가 다르며, 이는 데이터 이동과 메모리 접근 방식의 차이 때문이다.

- **퀵**: 제자리에서 분할하고, 배열을 양 끝에서 순차적으로 훑어 캐시 효율이 좋다. 그래서 가장 빠르다.
- **병합**: 비교는 퀵의 0.73배인데 시간은 1.3배다. 레벨마다 임시 배열로 옮겼다가 다시 복사하는 비용 때문이다.
- **힙**: 비교가 가장 많고, 부모(k)에서 자식(2k+1)으로 멀리 건너뛰며 접근해 캐시 효율이 낮다. 그래서 가장 느리다.

### 3.3 메모리 사용량

- **힙: 64 B로 일정, O(1)**. 입력 배열을 그대로 힙으로 쓰고, `sift_down`을 반복문으로 구현해 호출 깊이가 고정된다.
- **병합: 약 4n B, O(n)**. 임시 배열 4n에 재귀 스택 96 × (⌈log₂n⌉+1)이 더해진다 (n = 20,000: 80,000 + 1,536 ≈ 81,553). 전체의 98%가 임시 배열이다.
- **퀵: 약 1~2 KB, O(log n)**. 재귀 스택만 사용한다. n이 20배 늘어도 메모리는 약 1.5배만 늘었다.

### 3.4 피벗 선택 방법

- **First와 Random**: 입력이 이미 무작위라 비교 횟수와 재귀 깊이는 거의 같다. Random이 약 0.5 ms 느린 것은 `rand()` 호출 비용 때문이다. 분할 약 13,190회 × 38.8 ns ≈ 0.51 ms로, 측정된 차이와 거의 일치한다.
- **Median3**: 균형 잡힌 분할로 비교가 First보다 약 8% 적고, 재귀가 얕아져 스택도 가장 작다(First의 약 73%).
- **정렬된 입력**(n = 4,000, 추가 확인): First는 비교 약 800만 회(≈ n²/2), 스택 약 256 KB로 최악의 경우가 나타났다. Median3은 약 4.8만 회, Random은 약 6.4만 회로 최악을 피했다.

### 3.5 복잡도 비교

| 알고리즘 | 평균 시간 | 최악 시간 | 추가 공간 | 안정성 |
|---|---|---|---|---|
| 힙 정렬 | O(n log n) | O(n log n) | O(1) | 불안정 |
| 병합 정렬 | O(n log n) | O(n log n) | O(n) | 안정 |
| 퀵 정렬 | O(n log n) | O(n²) | 평균 O(log n), 최악 O(n) | 불안정 |

측정 결과에서도 세 알고리즘 모두 n log n에 비례해 증가했고, 공간은 힙 상수, 병합 n 비례, 퀵 log n 비례로 이론과 일치했다.

## 4. 결론

- **퀵 정렬**: 실제 실행시간이 가장 빠르지만, 피벗 선택이 중요하다. Median3이 비교 횟수와 메모리 면에서 가장 우수했다.
- **병합 정렬**: 비교 횟수가 가장 적고 안정 정렬이지만, 메모리를 n에 비례해 사용하고 복사 비용이 크다.
- **힙 정렬**: 비교 횟수와 실행시간은 가장 불리하다. 대신 최악의 경우에도 O(n log n)을 보장하고 추가 메모리가 상수라는 장점이 있다.
